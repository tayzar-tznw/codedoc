`iryo.reception` モジュールは、医療管理システムにおける受付端末アプリケーションの最上位レイヤーとして、システムの初期化、依存関係の構成、および受付業務全体のエンドツーエンドな実行手順を統括するオーケストレーションモジュールです。本モジュールは、起動点となる `Program.java` と、各業務シナリオをカプセル化した `flows` サブディレクトリで構成され、受付デスクで発生する日常的な運用タスクから締め処理、外部連携までのライフサイクル全体を制御する責務を担っています。

内部の連携において、`Program.java` は合成ルート（Composition Root）として動作し、基盤層（`iryo.kernel`）のDIコンテナを用いて通知、データアクセス、ロギングなどの共有サービスを初期化します。生成されたサービスプロバイダを起点として、`Program` は `flows` 配下の各業務フローコンポーネント（来院受付の `CheckInFlow`、請求・領収書発行の `AccountingFlow`、調剤連携の `PharmacyFlow` など）を順次実行します。各フローは Facade として機能し、ドメイン層、請求計算層、調剤層、外部・旧システム連携層といった複数の独立したサブシステムと対話しながら、個々の業務手順を疎結合かつ宣言的に連携させます。

アーキテクチャ面では、依存性の注入（DI）と合成ルートパターンの適用により、具象実装の結合度を最小限に抑え、保守性とテスト容易性を高めています。また、各業務フローを状態を持たない `final` ユーティリティクラスとし、単一の静的エントリーポイントを通じて実行させる設計を採用しています。純粋なドメインロジックの実行と業務シナリオのオーケストレーションを明確に分離し、新旧点数表の突合や事前条件の検証をフロー層に集約することで、複雑な医療受付業務における整合性の保証とシステム全体の高い見通しの良さを実現しています。
