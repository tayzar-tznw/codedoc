`iryo.reception.flows` ディレクトリは、医療受付システムにおける主要な業務シナリオや日常業務、運用タスクのエンドツーエンドな実行手順を統括・カプセル化するオーケストレーション層です。患者の来院受付を担う `CheckInFlow`、診療点数計算から請求・領収書発行を制御する `AccountingFlow`、処方箋受領から調剤・請求連携を行う `PharmacyFlow`、端末の日次締めを行う `DailyCloseFlow`、バイタル集計や外部連携出力を担う `ReportFlow`、およびシステムの健全性を検証する `MaintenanceFlow` で構成され、受付デスク周辺の具体的なビジネスユースケースを網羅しています。

アーキテクチャ面では、すべてのクラスがプライベートコンストラクタを持つ `final` ユーティリティクラスとして設計され、静的な `run()` メソッドを単一のエントリーポイントとして提供する Facade パターンを採用しています。各フローはドメイン層、請求計算層（`billing`）、共通基盤層（`kernel`）、調剤層（`pharmacy`）、外部連携層（`interop`）、および旧システム連携層（`legacy`）といった複数の独立したサブシステムを横断的に呼び出します。その制御において、Service Locator、Factory、Strategy、およびガード節などのパターンを適用し、複雑な依存関係と業務手順を疎結合かつ宣言的に連携させています。

本ディレクトリの重要な設計意図は、各ドメインの純粋なビジネスロジックを保持するのではなく、それらを組み合わせた「業務シナリオの実行と相互検証」の責務に特化している点です。新旧点数表の突合や多様なフォーマッタの実行、エンティティの監査記録、事前条件チェックなどをフロー内に集約することで、業務整合性の保証とシステム世代間の円滑な相互運用を実現し、受付業務機能の保守性と見通しの良さを高めています。
