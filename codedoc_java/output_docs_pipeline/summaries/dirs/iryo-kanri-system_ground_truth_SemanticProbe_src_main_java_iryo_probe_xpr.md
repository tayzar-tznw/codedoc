本モジュール（`iryo.probe.xpr`）は、Javaのインポート宣言による名前解決と型の束縛の違いが、システムの実行時挙動に与える影響を検証・実証するためのセマンティックプローブ群を提供することを目的としています。同一のソースコード記述であっても、インポートされる依存パッケージの違いによって異なる業務コンテキスト（管理側と受付側）の処理として解釈・実行されるメカニズムを比較評価するためのテストベッドとしての役割を担っています。

モジュール内を構成する主要コンポーネントである `AdminSide` と `ReceptionSide` は、対の比較対象として厳密に設計されています。両クラスの公開静的メソッド `run()` 内に記述された手続き（ログ記録、コード検証、ポイント換算処理）はテキストレベルで完全に一致していますが、前者は調剤系モジュール（`iryo.pharmacy`）、後者は請求・基幹ログ系モジュール（`iryo.billing`、`iryo.kernel.logging`）をインポートしています。これにより、共通の構文的手続きが異なるドメインモデルへと解決され、それぞれ固有の実行結果を返す連携・対比構造を形成しています。

設計面では、両クラスともにインスタンス化を完全に抑止したユーティリティクラスパターン（`final` クラス宣言およびプライベートコンストラクタ）が採用されています。状態を保持しない純粋な静的実行エントリポイントを提供することで、インスタンスの状態変化などの外部要因を排除し、純粋に「インポート解決の違い」のみを決定論的に検証・測定できるアーキテクチャ上の工夫が施されています。
