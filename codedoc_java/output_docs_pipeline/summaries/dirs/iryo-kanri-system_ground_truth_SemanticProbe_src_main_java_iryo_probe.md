本ディレクトリ（`iryo.probe`）は、医療管理システム（`iryo` 名前空間）におけるJava言語仕様に基づいた型解決、オーバーロード解決規則、インポートによる名前解決、およびスコープ遮蔽（シャドウイング）の正当性を実行時に網羅的に検証するためのグラウンドトゥルース検証ハーネス（セマンティックプローブ）を提供するモジュールです。製品コードを変更することなく、静的型推論やメソッド参照の束縛先シグネチャの検証を通じて、複雑なドメイン境界やモジュール間連携における静的・動的セマンティクスが仕様通りに動作しているかを決定論的に実証することを目的としています。

モジュールの中核となる `Program.java` は検証全体のエントリポイントであり、サブディレクトリの検証ケースと連携しながら十数項目の検査を統括します。具体的には、静的インポートと同一シグネチャによるメソッド隠蔽ルールを実証する `shadow` モジュールの `ShadowSide` や、同一構文コードがインポート先の差異（調剤系と請求系）によって異なる挙動へと分岐することを実証する `xpr` モジュールの `AdminSide`・`ReceptionSide` を呼び出し、その実行結果を照合します。さらに、`Program` 自身が `SerializedLambda` を用いてコンパイラがバインドしたメソッド記述子を動的に特定することで、多岐にわたる業務モジュール（`domain`、`billing`、`pharmacy`、`kernel` 等）の境界におけるシンボル解決の妥当性を評価します。

アーキテクチャ上の判断として、検証対象の挙動から状態変化などの外部要因を排除するため、各プローブクラスにはインスタンス化を完全に抑止したユーティリティクラスパターン（`final` 宣言および非公開コンストラクタ）が徹底されています。また、DIコンテナ、シングルトン、ストラテジー、ファクトリ、Fluent Interfaceといった各種デザインパターンの振る舞いや整合性の検証を包括しつつ、名前空間の競合や言語仕様の境界条件を個別モジュール内に局所化・カプセル化することで、システム全体に対して副作用を及ぼさない安全かつ厳密なテストベッドを確立しています。
