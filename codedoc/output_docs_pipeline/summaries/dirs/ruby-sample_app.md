`ruby-sample/app` ディレクトリは、図書管理システムのコアとなるビジネスロジック、データ永続化、および外部APIインターフェースを包括するアプリケーションの心臓部です。本モジュールは、RailsのAPI専用モードをベースに、MVC（Model-View-Controller）パターンを現代的に拡張した階層型アーキテクチャを採用しています。クライアントからのリクエストを処理する「コントローラ層（controllers）」、ドメインの概念とビジネスルールを表現する「モデル層（models）」、そして複雑なユースケースや横断的なロジックをカプセル化する「サービス層（services）」が明確に分離されており、システム全体の保守性、拡張性、およびテスト容易性を最大化するように設計されています。

これらのレイヤーは、依存関係の方向性を意識しながら密接に連携しています。クライアントからのHTTPリクエストは `controllers`（例: `BooksController`, `LoansController`）が受け取り、共通の例外処理やセキュリティ対策を適用した上で、処理を適切なコンポーネントへ委譲します。複雑な検索やビジネスロジックは、`services` の `BookSearch`（Query Object）や `FeeCalculator` に委譲され、コントローラを薄く保つ「Skinny Controller」が徹底されています。最終的に、これらのサービスやコントローラは、`models` における `Book`（STIによる `Ebook` や `ReferenceBook` を含む）、`Loan`、`Member` などのドメインモデルと相互作用し、データベースの永続化やビジネスルールの検証を行います。

アーキテクチャ設計においては、オブジェクト指向設計とドメイン駆動設計（DDD）のプラクティスが随所に取り入れられています。Active Recordパターンを基本としつつ、モデルの肥大化を防ぐために、単一テーブル継承（STI）によるポリモーフィズムの実現、不変な「値オブジェクト（Value Object）」である `Money` クラスの導入、共通処理を切り出す「Concerns（`Searchable`）」、そして単一責任の原則に従う「サービスオブジェクト（Service Object）」パターンなどが効果的に組み合わされています。これにより、ドメインモデルの表現力を高めながらも、各コンポーネントが疎結合に保たれ、将来的な機能追加や仕様変更に強い、堅牢なシステム基盤を構築しています。
